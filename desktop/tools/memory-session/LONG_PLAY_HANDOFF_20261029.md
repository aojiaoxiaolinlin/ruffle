## 在另一台机器上的顺序

先保存那台机器自己的未提交工作，再获取私有同名分支；工作区干净时可执行：

```text
git fetch private
git switch codex/roco-memory-investigation
git pull --ff-only private codex/roco-memory-investigation
```

若 private 尚未配置，添加 https://github.com/aojiaoxiaolinlin/ruffle-A.git。
默认分支 0.7.1-A 不合并、不覆盖。不要仅取旧 fork 而漏掉私有仓库昨晚的两次提交。

1. 优先找测试者要本次高占用的整个日志目录，尽量在他再次启动覆盖前取回。
   另记游戏名称、大致游玩时长、截图时间、是否停战；未知信息明确留空。
2. 核验日志时间及版本；若可取得 EXE，记录 SHA256。先看是否包含资源诊断行。
   缺少诊断项表示未知，不当作零；旧日志不够时只陈述限制。
3. 若旧日志不可得，按 LONG_PLAY_CAPTURE.md 安排后续正常游玩自动采集。
   每轮 session.json 明确 gc_work_floor_enabled=0 或 1，不能混入一条曲线。
   最新 GC 源码以开关 0 运行可作为该实现的关闭组，但不能冒充截图中的原始 EXE。
4. 对齐进程 private commit、工作集、系统提交余量、GC 阶段及对象数、影片数、资源容量。
   看增长与完整周期的关系，再决定是否需要原生堆快照，避免仅凭总量判断根因。
5. 同时分析 Desktop perf、Perf progress、Perf phase、Perf stall：检查重绘吞吐、
   帧间隔、P95/最大耗时及长耗时次数，核对 GC 是否增加暂停。细则见采集说明的“同时检查流畅度”。
   现有日志不提供端到端输入延迟；前后台、加载和目标帧率应纳入判断，不能仅凭平均 FPS 说不卡。

自动脚本需要与 EXE 配套的 build-identity.json、PDB；详细要求见采集说明。
如重新构建 Windows 诊断版，记下实际提交和二进制哈希，保存配套文件，禁止复用旧身份文件。
目前 Linux/WSL 本轮只完成脚本 PowerShell 语法检查及文本差分检查，未实跑新的 Windows 采集。
