# 下一阶段 GPU 中间目标优化计划

状态：分析与计划，尚未修改渲染行为。继续使用开发分支
`codex/local-blend-filter-resolution`，基准为 `0.7.1-A`。

## 已确认的代码路径

1. `render/wgpu/src/surface/region.rs` 中，空形状的 `bounds=None` 会立即返回
   `EmptyOrOffscreen`，未继续检查后续可见命令；整个命令列表没有输出或最终范围
   完全离屏，也返回相同原因。所以日志的 79129 次不能全部当作可跳过图层。
2. `surface/commands.rs::blend` 对任意失败结果调用 `.ok()`，丢失原因后按父画布
   尺寸创建 Surface。真正整体为空的层目前同样走整尺寸目标。
3. Normal / Layer / Add / Screen / Subtract 都归入 `BlendType::Trivial`。
   这里只表示合成能用固定混合状态表达；这些隔离层仍先渲染到完整父目标，不能将
   `trivial` 解读为没有中间纹理开销。
4. `independent_blend` 对 Alpha/Erase、Shader、任何遮罩命令保守回退；即使子图层
   本身独立，外部 `num_masks != 0` 也会禁止延迟准备。`chunk_blends` 会先构建整个
   `Vec<Chunk>`，部分层的纹理因此早于实际合成时刻分配，并通过 Chunk / DrawCommand
   持有到消费。缺少峰值时资源类型分解，目前不能断言这独自解释全部 1.26 GiB 峰值。
5. `CommandTarget::take_color_texture` 会消费 target，保留需要合成的颜色/resolve
   纹理，释放其它可释放成员；不能把这一过程误判为“MSAA 一直保存到所有兄弟合成完”。
   但递归渲染中的祖先目标与已准备的兄弟颜色纹理仍可能同时存在。
6. 现有精确规格纹理池、32 像素边界分档和 256/128 MiB 空闲预算继续保留。
   需要验证尺寸规格竞争，不预先认定为新局部目标造成的回退。

## 第一阶段：明确无输出，安全跳过

将“内容边界分析”与“是否值得分配局部目标”分开。建议内部结果为：

```text
内容：Empty / Known(bounds) / Unknown(reason)
决策：Skip / Local(rect) / Full(reason)
```

- 单个可证明没有可绘制几何的形状忽略后继续扫描，后面可能仍有可见位图或形状。
  `bounds=None` 本身不自动证明空；应区分没有索引/可绘制几何与无效/非有限边界。
- 必须检查完整命令列表；遇到未知、遮罩、祖先依赖或 Shader 时保守走原路径。
- 只有完整列表已被证明无输出，或者其保守范围与当前目标完全不相交，才能 Skip。
  不通过纹理透明像素扫描、GPU readback 或动态显示对象边界缓存证明不可见。
- 第一次只覆盖现有 7 种局部复杂混合候选、外部无遮罩、二维纯绘制路径。
  它们的透明前景不改变目标；跳过发生在创建 Surface / 背景副本之前。
- 不将 Alpha/Erase 或 Shader 纳入这条规则，不变更它们现有渲染/层隔离语义。
- 计数独立为“空列表/无几何/整体离屏/未知边界”，增加 skipped 数与避免的理论目标
  像素面积。skipped 不是 cropped；新统计需保持各去向数量守恒。

验收：空形状 + 可见位图不能被错误跳过；未知命令 + 空形状继续保守；完全离屏
候选不产生该图层的中间目标或背景副本；后续可见兄弟的画面和顺序不变。
日志先前 79129 次只是优化候选池，不承诺能全部消除。

## 第二阶段：缩小普通隔离图层

先同步把 trivial 按实际 Normal / Layer / Add / Screen / Subtract 计数，记录外部
mask 状态、目标尺寸及面积；同时将 checkout 分为 MSAA color、single-sample color、
stencil 等，检查峰值主要持有什么资源。只周期汇总，不逐层输出日志。

第一批扩展局部目标到无遮罩、无祖先依赖、边界可证明的二维叶子隔离层：

- 保留真实离屏隔离与合成，不把 Layer 或 Normal 无条件展开到父目标。
- 局部纹理按原宽高比及像素分辨率渲染；合成矩阵同时补回原点与尺寸。
  当前 trivial 分支的矩阵只使用目标宽高，不能只修改 Surface 尺寸而遗漏位置。
- Layer 含 Alpha/Erase、嵌套混合/遮罩时保留原路径，直到有完整的依赖和边界证明。
- 复用第一阶段三态边界与 Skip，保护边、尺寸分档及现有全尺寸对照开关保持一致。
- 不调整主画布分辨率、MSAA 质量、BitmapData 像素或总缓存预算。

验收：Normal / Layer / Add / Screen / Subtract 的透明边缘、局部位置、旋转、负坐标、
非整数缩放、位图子区域与 pixel snapping；必须包含 Layer 中 Alpha/Erase 保持回退
的反例。收益按全部目标面积、新建字节、峰值及耗时判断，而不是只看候选命中率。

## 第三阶段：缩短遮罩下的纹理持有时间

优先评估“子命令列表独立，但外部存在遮罩”的延迟准备，不直接取消 num_masks 判断。

- 明确延迟操作处于写入遮罩、绘制被遮罩内容还是清理遮罩阶段；保留 push / activate /
  deactivate / pop 顺序、stencil 深度与引用值。
- 子层在独立目标中准备，合成仍使用父目标当时的 stencil / alpha mask 状态。
  当前 Deferred 只存命令；新准备器从零 mask 状态开始，需显式衔接外部状态，不能
  仅删除外部 guard，否则可能漏掉最终合成的遮罩。
- 初版只支持外部“绘制被遮罩内容”阶段、子命令可证明不读祖先且不包含内部遮罩的
  情况；写入/清理 stencil、祖先 Alpha/Erase、Shader 继续原路径。
- 将准备动作移到实际消费点，缩短兄弟颜色纹理在 Vec<Chunk> 中的持有，不交换绘制
  顺序，也不使用 Texture::destroy 破坏已提交 GPU 命令的资源。
- 内部完整遮罩组、祖先依赖图层与全图流式 chunk 消费留待后续独立分析，不混入首批。

验收：多层遮罩、兄弟交替遮罩、stencil 写入/清理、透明遮罩、Layer + Alpha/Erase、
滤镜 + CAB 的像素回归。固定兄弟数量增长测试应降低持有峰值；单条深依赖链可能仍需
较高峰值，不承诺消除必需的同时存活资源。

## 验证与推进方式

每阶段独立修改、独立验证，可分别提交，不将三项一次捆绑：

1. 先构造针对性 GPU 场景和边界/调度反例，再改行为。既有混合、遮罩、滤镜、CAB、
   九宫格回归沿用现有预期及容差，不通过放宽容差掩盖裁切/遮罩错误。
2. Vulkan / GLES，Low / Medium / High；画面裁切与调度错误要求修正，已知旋转
   光栅化舍入差异需按既有固定探针规则量化，不扩大成通用容差。
3. 固定画布、质量、预算及游戏路线。先将模糊保持100%，同一程序对照新策略开/关；
   再叠加50%模糊。记录实际帧数、skipped / cropped / fallback、目标面积、
   新建字节/帧、各类 checkout 峰值、CPU render 平均/P95/最大值、allocator 数据。
4. 手机继续100%画布 + GLES + Medium + 128 MiB空闲预算，检查仓库、对战和长时间
   跑图。同步区分任务管理器专用/共享GPU内存与allocator/checkout指标。
5. 固定场景里目标分配、持有峰值或渲染耗时有可重复改善，且无图像/输入/稳定性回归，
   再推进下一阶段。若规格数/淘汰增多抵消收益，先调整尺寸复用策略，而不是加缓存。
6. 验证确认的公用修改及时合回 `0.7.1-A`；安卓前端设置和平台专属策略单独处理。

不预设每阶段提升百分比。统计开销、首次加载与稳态渲染分开评估，旧日志不作为
同路线 A/B 的替代。本轮产物仅为此计划文档，生产代码和渲染行为未改变。
